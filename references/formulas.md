# 公式与阈值速查

> **权威来源**：仓库 `docs/定盘实时任务_公式清单.md`（只读，禁止改动）。本文件仅为脚本实现索引，如两者冲突，以公式清单为准。
> 所有阈值都可在 `output/config.json` 的 `thresholds` 中覆盖，无需改代码。

## 一、大盘红绿灯 `common.market_light`

```
MA5/MA10/MA20 = 上证近 5/10/20 日收盘均值
红线 = MA20 × 0.98
上证 >= MA20        → 绿灯，仓位上限 100%，单票 40%
MA10 <= 上证 < MA20 → 黄灯，单票 20%
上证 < MA10         → 红灯，不给买点
上证 < 红线         → 红灯（severe），仓位上限 20%
```

## 二、主线判定 `common.score_days`

```
每日：板块涨幅进 TOP5 → +2；涨幅 >= 0.8% 且 成交额 >= 150亿 → +1
3 日累计：>= 4 ⭐主线；2-3 👁观察；1 ↻轮动
存档文件：主线存档.json（每日收盘由 daily.py 写入板块 TOP20）
```

## 三、龙头三条件 `preopen.build_leaders`

```
① 正宗：Agent 业务知识判断（脚本不判）
② 有记忆：zt60 = 近60日涨幅>=9.5% 天数，>= 3 标 ★
③ 强度：按连板数 lbc 降序（lbc = 末尾连续涨停天数）
```

## 四、趋势确认 `common.trend_ok`（硬门槛）

```
up   = MA5今 > MA5昨 且 现价 > MA5今
zt5  = 近5日内有涨幅 >= 9.5%
trend = (up or zt5) 且 现价 > MA10
```

## 五、买点 `common.buy_signal`

```
形态：-2% <= 当前涨幅 <= +6%  且  2% <= 回落 <= 8%
回落 = (当日最高 - 现价) / 当日最高 × 100
四件套：① 回落段均量 <= 冲高段均量 × 0.85
        ② 最低点出现后 >= 10 分钟未破
        ③ 现价 > 3分钟前价 且 近3分钟量 > 前3分钟量 × 1.1
        ④ 同板块 >= 1 只票近3分钟回升
位置：|现价/昨收 - 1| × 100 <= 1.5%  或  现价 >= VWAP
A级 = 形态 + 四件套全齐 + 位置达标；B级 = 形态 + 位置达标但四件套不齐
```

## 六、三不买 `common.blocked`

```
首阴：昨日涨幅 >= 9.5% 且 现价 < 昨收 × 0.99
破位：现价 < MA10
后排：现价 < 同板块最强票价 × 0.99
      · 同板块最强票 = common.sector_strongest：先检索东财板块成分股（按涨幅最大者的现价），
        板块无对应或接口不可用时回退候选池同板块列
```

## 七、卖点风控 `common.exit_signal`

```
浮盈亏 = (现价/成本 - 1) × 100
现价 <= 自设止损价 → 🔴 卖出
浮盈亏 <= -5%      → ⛔ 强制止损
<= -3%             → ⚠️ 止损预警
<= -2% 且 非绿灯    → ⚠️ 减仓提示
现价 >= 目标价      → 🟢 止盈
```

## 八、仓位 `common.position_plan`

```
绿灯单票 = 总资金 × 40%；黄灯 × 20%；红灯不开仓
止损价 = min(当日最低, 现价 × 0.95)
```

## 九、竞价选股 `common.preopen_filter`

```
高开 2% <= pct <= 9.5%；3 <= 价 <= 50 元
30亿 <= 流通市值 <= 400亿（新浪 nmc 单位万元，脚本 /1e4）
剔除 ST / 退市 / 北交所(4、8、92 开头)
取 TOP15，前 8 只写入 候选池.txt（板块列留空待 Agent 回填）
昨日涨停延续度：>=+2% 延续；-1%~+2% 分歧；<-1% 退潮
```

## 十、时段分流 `common.current_stage`

| 时段 | stage | 内核 |
|---|---|---|
| 9:25-9:35 | preopen | preopen.py |
| 9:35-11:30 / 13:00-15:00 | watch | watch.py |
| 15:00-15:35 | freeze | 数据定格中 |
| 15:35-23:59 | daily | daily.py |
| 周末/非交易时段 | closed | 一行提示 |

## 十一、交易日历 `common.calendar_status` / `common.calendar_refresh_hint`

```
配置项：config.json 的 calendar = { holidays[], coverage_to, generated_at, source, lead_days }
内置基线：2026 年沪深北休市安排（仅列"落在工作日"的 19 个休市日，来源：上交所公告）
休市判断：current_stage = 周末(weekday>=5) 或 当日 in holidays
临期检测：days_left = coverage_to - today；days_left <= lead_days(默认30) 或已到期 → refresh_needed
刷新：各阶段末尾输出刷新指引 → Agent 联网搜索下一期休市安排 → run.py calendar set ...
```

## 十二、数据源与降级

```
数据源：仅 腾讯(实时/分时/日K) + 新浪(全市场快照/nmc) + 东财(板块排行/成分股/个股板块/涨停池) 直连
降级：common.note_degraded(source, detail) 收集；common.degraded_note() 汇总为一行
      文本输出追加"⚠️ 数据源降级：…"，--json 的 degraded 字段透出
缓存：暂不缓存；--offline 读取 assets/sample 样例，仅用于演示/验证
```

3. **涨停延续度的「今日竞价」取数时点**：脚本取昨日涨停股在 9:25 竞价的涨跌幅，清单未写明取数时点。
4. **交易日历**：内置 2026 基线，临期由脚本提示、由 Agent 联网搜索刷新（数据源限定腾讯/新浪/东财，脚本不含日历接口）。
5. **账户/持仓参数**：清单未定义存放位置，本技能以 `output/config.json` / `output/positions.json` 落地，由 Agent 向用户提问收集。

7. **盘中「今日」取数时点**：`trend_ok` 与「首阴」依赖日 K 末根，盘中日 K 可能不含当日实时，清单未写明取数时点。
