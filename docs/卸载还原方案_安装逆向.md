**目标**：把环境还原到「安装前」状态，覆盖用户选定的四层范围——① 卸载技能本体 ② 还原定时任务 ③ 恢复用户旧系统 ④ 回滚配置与数据偏离。

## 三、设计原则

1. **绝不硬删**：一切移除 = `shutil.move` 到回收站 `~/.codebuddy/.trash/<时间戳>/`；永久删除仅 `--purge` 显式开启。
2. **默认预演**：无 `--apply` 即 dry-run，只打印计划；执行须 `--apply --yes` 双确认。
3. **幂等**：目标不存在即跳过并记录，重复执行安全。
4. **防丢优先**：先导出运行时数据与回滚配置，再做破坏性移除。
5. **自包含**：不 `import` 项目内模块，技能目录被移除时脚本仍可运行；技能目录**最后**移除。
6. **可审计**：全过程与结果写入 `uninstall_report.json`，含参数、动作清单、逐条记录、错误。
7. **危险操作设闸**：技能目录须含 `SKILL.md` 才予移除；还原目标已存在默认跳过（`--on-exists replace` 才覆盖，且原目标先入回收站）。

## 四、执行顺序（及理由）

```
预检 → ①回滚配置 → ②导出运行时数据 → ③还原旧系统 → ④移除镜像 → ⑤移除技能 → ⑥输出任务动作 → ⑦校验
```

- **先回滚配置、再导出数据**：确保被移入回收站的 `config.json` 已是干净状态（否则技能内 `output/` 一带走就再无从回滚）。
- **还原旧系统在移除技能之前**：备份与技能目录互不影响，但先还原便于「旧系统已还原」参与最终校验。
- **技能目录最后移除**：脚本可能正位于该目录内，先完成其余步骤再移动自身所在目录。
- **任务动作先于校验告知**：平台侧任务由 Agent 执行，脚本只产出动作清单，不越权操作平台调度器。

---

## 五、定时任务还原（关键）

脚本**不直接操作平台调度器**，而是产出结构化的 `schedule_actions`（见报告 JSON），由 Agent 调平台能力执行：

```json
{
  "delete_task":  { "id": "11658801", "name": "A股实盘助手" },
  "restore_task": { "id": "11182153", "spec": null }
}
```

- **删除新任务**：`11658801`（安装期创建，须先停用/删除，避免卸载过程中仍被触发）。
- **重建原任务**：原 `11182153` 在报告中记为「已不存在」，其 `cron/时区/入口/超时/重试` 规格未留存。处理优先级：
  1. 提供 `--old-task-spec <json>`（若安装期导出了原任务规格）→ 脚本读入并写入动作清单，Agent 据此原样重建；
  2. 规格缺失 → 脚本显式告警，需**用户确认原任务内容**后由 Agent 重建，或从回收站/备份中的旧配置恢复；
  3. 无法确认时**不臆造**——仅删除新任务，并提示用户手动重建。
- 参考：原系统任务应为「每 10 分钟运行旧 `/workspace/交易系统` 脚本」一类；但**不得据此臆断**，以用户确认或留存的规格为准。

## 六、数据与配置回滚细节

- **规则偏离回滚**：`confirmations.backrow_basis` 安装期被改为 `pct`，回滚为清单原文默认 `price`；`mainline_source` 若被改亦回滚为默认 `sina`（见 `scripts/common.py` 的 `CONFIRM_RULES`）。
- **扫描位置**：`--data-dir` 指定的目录 + 镜像目录 `/workspace/定盘数据/` + 技能内 `output/`（在导出前处理），去重后逐个回滚。
- **迁移数据**：安装期把旧系统 txt/逗号格式转成了技能 JSON/管道符格式；**还原以安装期完整备份 `/workspace/交易系统_备份_20261009/` 为准**，`copytree` 回 `/workspace/交易系统`，备份保留。
- **安装后新增的运行时数据**（持仓/候选池/history 等）：先整体移入回收站 `skill_output/`，不会静默丢失；如需要可再从回收站取回。
- **清单只读**：公式清单不属于还原范围，脚本不触碰。

## 七、CLI 用法

```bash
# 0) 只读扫描：与 docs/cw_setup_info.md 逐项比对（AI 代还原第一步；`--json` 供程序化比对）
python scripts/uninstall.py --scan --json

# 1) 预演（默认，不改动任何文件）
python scripts/uninstall.py --plan

# 2) 执行（四层全还原）
python scripts/uninstall.py --apply --yes

# 3) 自定义路径 / 覆盖已存在的还原目标 / 提供原任务规格
python scripts/uninstall.py --apply --yes \
  --skill-dir   ~/.codebuddy/skills/a-stock-selection \
  --backup-dir  /workspace/交易系统_备份_20261009 \
  --restore-to  /workspace/交易系统 \
  --mirror-dir  /workspace/定盘数据 \
  --on-exists replace \
  --old-task-spec /path/to/old_task.json

# 4) 执行后连回收站一并永久删除（危险，默认关闭）
python scripts/uninstall.py --apply --yes --purge
```

主要参数：`--scan`（只读扫描比对）、`--scan-root`（技能检索根，可多次）、`--report`（用户实际【安装评估报告_*.md】路径，缺省自动发现）、`--report-root`（报告检索根，可多次）、`--json`、`--plan/--apply/--yes`、`--skill-dir`、`--backup-dir`、`--restore-to`、`--mirror-dir`、`--trash-root`、`--data-dir`（可多次）、`--on-exists skip|replace`、`--new-task-id`、`--old-task-id`、`--old-task-spec`、`--purge`。

**参数优先级**：命令行显式传入 > 用户实际报告解析值 > 内置默认。即：路径/任务 ID 缺省时，脚本会自动发现用户环境中的「安装评估报告_*.md」并以其解析值驱动还原；未发现时才回退 `docs/cw_setup_info.md` 记录的内置默认。换环境时用参数覆盖即可。

> **原备份点保留**：`--backup-dir` 指向的安装期备份**还原后不删除**；脚本对其设红线（不得与被操作路径重合/被包含），`--purge` 也不涉及备份，并在校验中确认「原备份点已保留」。AI 代还原的标准流程见 [交付设计_AI代还原.md](./交付设计_AI代还原.md)。

## 八、边界与风险

| 风险 | 处置 |
|---|---|
| 安装后用户改过数据 | 先导出到回收站 `skill_output/`，可回溯取回 |
| 还原目标已存在 | 默认跳过（幂等）；确需覆盖用 `--on-exists replace`，原目标先入回收站 |
| 原任务规格丢失 | 不臆造；告警并要求用户确认后重建 |
| 技能目录名/结构异常 | 预检要求含 `SKILL.md`，否则中止 |
| 脚本自身在技能目录内 | 技能目录最后移除；脚本自包含，不依赖项目模块 |
| 权限不足 / 路径只读 | 逐条记录为 error，退出码非 0，不影响其余步骤 |
| 误删担忧 | 全流程零硬删；`--purge` 为唯一致删开关 |

## 九、验收标准

`--apply` 后逐项通过：

1. `~/.codebuddy/skills/a-stock-selection` 已不存在；
2. `/workspace/交易系统` 已还原（含备份原件内容）；
3. `/workspace/定盘数据` 已不存在；
4. 残留的 `config.json` 中 `confirmations.backrow_basis == "price"`；
5. 回收站生成 `<时间戳>/`（含 `skill_dir/ skill_output/ mirror_data/ uninstall_report.json`）；
6. 报告 JSON 的 `schedule_actions` 已交由 Agent：新任务 `11658801` 删除、原任务 `11182153` 按确认规格重建；
7. **原备份点 `/workspace/交易系统_备份_20261009/` 仍存在**（报告 `backup.preserved=true`）；
8. 命令退出码为 0。
