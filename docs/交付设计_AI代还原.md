# 交付设计 · AI 代还原（a-stock-selection）

> 渠道：**AI 代还原**（用户把「还原」诉求 + 本文指令模板发给 AI，由 AI 先扫描环境、与安装报告比对，再执行还原）
> 依据：**用户环境中的实际报告**「安装评估报告_*.md」（如 `安装评估报告_a-stock-selection.md`）＋ 项目基准 [docs/cw_setup_info.md](./cw_setup_info.md) ＋ [docs/卸载还原方案_安装逆向.md](./卸载还原方案_安装逆向.md) ＋ 脚本 [scripts/uninstall.py](../scripts/uninstall.py)
> 原则：**先扫描发现报告并比对差异、后还原；以用户实际报告为事实源；原备份点保留不删**

---

## 一、交付目标与硬约束

**目标**：把用户环境还原到**安装前**状态——卸载技能本体 → 还原定时任务 → 恢复用户旧系统 → 回滚配置与数据偏离。

**硬约束（红线，AI 必须遵守）**：

1. **先扫描、后还原**：不得凭默认路径臆断。先运行 `--scan` **发现用户环境中的实际报告「安装评估报告_*.md」**，解析其字段并与项目基准 `docs/cw_setup_info.md` **逐项比对差异**；再以**用户实际报告**的取值（技能目录/备份目录/镜像目录/任务 ID 等）驱动还原。路径/版本/指纹不符时**先报告差异、请用户确认**，不得径直执行。
2. **原备份点必须保留**：`/workspace/交易系统_备份_20261009/`（安装期备份）**还原后仍保留，不删除**。脚本对备份点设红线（不得与被操作路径重合/被包含），`--purge` 亦不涉及备份。
3. **零硬删**：一切移除 = 移入回收站 `~/.codebuddy/.trash/<时间戳>/`；永久删除仅 `--purge` 显式开启，且不含备份点。
4. **默认预演**：无 `--apply` 即 dry-run；执行须 `--apply --yes` 双确认。
5. **不臆造**：原定时任务 `11182153` 规格未知时，只删新任务并请用户确认重建，禁止编造 `cron/入口`。
6. **公式清单只读**：`docs/定盘实时任务_公式清单.md` 不得改动。

用户把下方指令模板（见[附录](#附录用户指令模板复制即用)）发给一个**支持联网/可执行命令**的 AI。

```text
3) 原备份点（/workspace/交易系统_备份_20261009）保留，不要删除。
```

## 四、AI 代还原标准流程（SOP）

> 供 AI 执行；每步给出命令与判据；任一步不符即停下并告知用户。

**步骤 1 · 发现用户实际【安装评估报告】并定位技能目录（检索，非臆断）**
在用户环境中检索文件名形如 `安装评估报告_*.md`（例如 `安装评估报告_a-stock-selection.md`）的报告（检索根：cwd / 工作区 / `docs/` / 技能父目录 / `/workspace`）；同时按 `SKILL.md` 的 `name: a-stock-selection` 定位实际技能目录。**以用户实际报告为事实源**；与项目基准 `docs/cw_setup_info.md` 默认路径不一致时，以实际报告为准并记入差异。

**步骤 2 · 环境扫描（只读；自动发现报告）**

```bash
python scripts/uninstall.py --scan --json \
  --scan-root ~/.codebuddy/skills \
  --report-root ~/.codebuddy/skills        # 可多次；缺省自动检索 cwd/项目/docs/技能父目录/workspace
# 报告不在默认检索范围时显式指定：
python scripts/uninstall.py --scan --json --report "/path/to/安装评估报告_a-stock-selection.md"
```

**步骤 3 · 差异分析（用户实际报告 vs 项目基准）＋ 环境核对**
脚本已内建两步比对，向用户呈现：
1. **报告差异表**：`install_report.diff_vs_baseline` —— 文本报告中「用户实际报告 vs 项目基准」逐字段差异（技能目录 / 版本 / 清单 sha256 / 环境清单 / 备份目录 / 镜像目录 / 新任务 ID / 原任务 ID / cron / 任务名 / 规则偏离等）；
2. **环境核对表**：`items` —— 以用户实际报告取值核对环境现状（存在/缺失/不符）。

| 项 | 报告描述（事实源＝用户实际报告） | 实测 | 判定 |
|---|---|---|---|
| 技能目录 | 报告解析值 | … | ✓/≠/✗ |
| 版本 | 报告解析值 | … | |
| 清单 sha256 | 报告解析值 | … | |
| 迁移数据 | 报告解析值 | … | |
| 镜像目录 | 报告解析值 | … | |
| 备份点 | 报告解析值 | … | |
| 还原目标 | 应缺省 | … | |
| 规则偏离 | `backrow_basis=pct` | … | 需回滚 |
| 定时任务 | 报告解析的新/原任务 ID | … | |

> 还原参数按 `effective_params`（`skill_dir`/`backup_dir`/`mirror_dir`/`restore_to`/`new_task_id`/`old_task_id`/`new_task_name`）生效，均来自**用户实际报告**；命令行显式传入的同名参数优先。

**步骤 4 · 备份红线确认**
`backup_dir` 必须存在且**不**落在技能目录/镜像目录/还原目标之内（脚本预检会拦截）；备份存在＝可还原旧系统，缺失＝只能卸载技能与清理镜像，须提示用户。

**步骤 5 · 预演**

```bash
python scripts/uninstall.py --plan --yes
```

**步骤 6 · 执行（保留备份）**

```bash
python scripts/uninstall.py --apply --yes
```

顺序：回滚 config → 导出运行时数据 → 还原旧系统 → 移镜像 → 移技能 → 任务动作 → 校验（含「原备份点已保留」）。

**步骤 7 · 定时任务还原（平台侧，由 Agent 执行）**
读取报告 JSON 的 `schedule_actions`：
- `delete_task`：删除新任务 `11658801`（A股实盘助手，`0 */10 * * * *`）；
- `restore_task`：按 `--old-task-spec`（若提供）重建原任务 `11182153`；**规格未知时向用户确认**，确认前只删新任务。

**步骤 8 · 输出【AI 代还原报告】并转述**
字段：扫描差异表 / 判定（一致|偏离|缺失）/ 已执行动作 / 回收站路径 / 备份点保留确认 / 定时任务处理 / 校验结果 / 残留风险。

## 五、扫描比对基准与事实源

- **事实源＝用户实际报告**：脚本在用户环境检索 `安装评估报告_*.md`（`--report` 显式指定 / `--report-root` 指定检索根），解析技能目录、版本、清单 sha256、环境清单、备份目录、镜像目录、新/原任务 ID、cron、任务名、`backrow_basis` 等字段，并以这些取值驱动还原。
- **比对基准＝项目报告 `docs/cw_setup_info.md`**：解析同一批字段，与用户实际报告做**逐字段差异比对**（`diff_vs_baseline`）。
- 解析字段缺失时回退内置基准（`REPORT_REF`/`EXPECT`）；`docs/cw_setup_info.md` 的内置基准值如下（示例，供对照）：

| 基准项 | 值 |
|---|---|
| 安装时间 / 平台 | 2026-10-09 20:58 ｜ WorkBuddy |
| 版本 | `v5` |
| 公式清单 | v3 主线龙头低吸版，sha256 `a9950cf9045236953a60cbec50da020d883a1fcd73dfd51d77807a1d886d6b27` |
| 迁移数据文件 | `positions.json`、`候选池.txt`、`history/`、`最新数据.json` |
| 镜像目录文件 | 上述 + `config.json` |
| 安装期被改写的规则 | `confirmations.backrow_basis = pct`（默认 `price`，须回滚） |
| 新/原任务 | `11658801` / `11182153` |

> 扫描只读、不做任何改动；`--json` 供 AI 程序化比对（含 `install_report`、`effective_params`），文本模式供人工核对。

## 六、安全边界（AI 必须遵守）

- ❌ 禁止删除原备份点（脚本以红线拦截 + 校验「原备份点已保留」）。
- ❌ 禁止 `rm -rf`；移除一律经回收站；`--purge` 不含备份点。
- ❌ 禁止在未扫描比对、或差异未确认时执行 `--apply`。
- ❌ 禁止臆造原任务 `cron/入口`；规格未知先问用户。
- ❌ 禁止改动公式清单。
- ✅ 路径与报告不符时，先报告差异并请用户确认实际路径。
- ✅ 备份缺失时明确告知：只能卸载技能与清理镜像，旧系统无法还原。

## 七、异常处理

| 现象 | 处理 |
|---|---|
| 技能目录不在默认路径 | 以 `--scan` 检索结果为准，用 `--skill-dir` 指定；记入差异 |
| 备份点缺失 | 提示无法还原旧系统；仅卸载技能、清理镜像，保留其余不动 |
| 还原目标已存在 | 默认跳过（幂等）；确需覆盖加 `--on-exists replace`（原目标先入回收站） |
| 备份点落在被操作路径内 | 预检红线拦截，拒绝执行，须改用独立备份路径 |
| 原任务规格未知 | 只删新任务，向用户确认后重建，不臆造 |
| 扫描发现版本/指纹不符 | 停止，先与用户核对环境，不径直还原 |
| 权限不足/路径只读 | 逐条记为 error、非 0 退出，不波及其余步骤 |

## 八、验收清单

1. `--scan` 输出与 `docs/cw_setup_info.md` 的差异表，判定合理；
2. `--apply --yes` 退出码 0；
3. 技能目录已移除；镜像目录已移除；
4. `/workspace/交易系统` 已从备份还原；
5. **原备份点 `/workspace/交易系统_备份_20261009/` 仍存在**（`uninstall_report.json` 的 `backup.preserved=true`）；
6. 残留 `config.json` 的 `backrow_basis == "price"`；
7. 报告 `schedule_actions` 已交由 Agent：删新任务、按确认规格重建原任务。
